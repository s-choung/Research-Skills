
# bullets: 산문을 계층형 불릿으로 (예전 bulletization)

긴 문단을 계층 불릿으로 재배치한다. 목적은 훑어 읽기다. 독자가 최상위 불릿만 읽어도
결론이 잡히고, 근거가 필요할 때만 하위 불릿으로 내려가게 만든다.

ko-writing과 함께 쓴다. 문체 교정을 먼저 끝내고 구조 재배치는 그 다음이다.
순서를 바꾸면 불릿마다 다시 교정해야 한다.

## 핵심 규칙

1. **한 불릿 = 한 주장.** 두 주장이 한 불릿에 있으면 쪼갠다.
2. **계층의 의미를 고정한다.**
   - 최상위: 주장, 결론, 해야 할 일.
   - 하위 1단계: 그 주장의 근거, 수치, 방법, 예외, 대안.
   - 하위 2단계까지만. 3단계가 필요하면 상위 구조가 잘못된 것이니 최상위를 다시 나눈다.
3. **최상위만 읽어도 글이 되는지 확인한다.** 하위 불릿을 전부 가려도 논지가 이어져야 한다.
4. **순서는 결론 먼저.** 배경과 경위는 결론 뒤로 보내거나 하위로 내린다.
5. **문장 내용은 바꾸지 않는다.** 구조 재배치이지 재작성이 아니다. 쪼개면서 필요한
   최소 수정(접속사 제거, 지시어를 명사로 환원)만 허용된다.
6. **불릿 형태를 문단 안에서 통일한다.** 같은 목록에서 명사형 종결과 -다체를 섞지 않는다.
7. **한정, 예외, 대안은 문장에 끼우지 말고 하위 불릿으로 내린다.**
   "A로 하되 B도 가능하고 C면 예외다"가 아니라 "A로 한다" 아래에 `- 대안: B`,
   `- 예외: C인 경우`.
8. **라벨 불릿 금지.** "1. **제목**: 설명" 형태 대신 평서 불릿과 들여쓰기로 푼다.
   (ko-writing doc-style과 같은 방향.)

## 변환 예시

전 (산문):

> 이 페이지는 연구의 LLM 절반을 담습니다. 짝이 되는 리포트는 이제 첫 번째 질문만
> 다룹니다. 두 번째 부분은 메커니즘을 묻는데, 벤치마크의 surrogate가 결정론적
> ridge regression이라 각 round를 복원할 수 있어서 pick을 그 순간의 랭킹에 견줘
> 채점할 수 있기 때문입니다. 새로 발생한 API 비용은 없습니다.

후 (계층 불릿):

- 이 페이지는 연구의 LLM 절반을 담습니다.
- 짝이 되는 리포트는 이제 첫 번째 질문만 다룹니다.
- 두 번째 부분은 메커니즘을 묻습니다.
  - 벤치마크의 surrogate가 결정론적 ridge regression이라 각 round를 복원할 수
    있고, 따라서 pick을 그 순간의 랭킹에 견줘 채점할 수 있습니다.
- 새로 발생한 API 비용은 없습니다.

## HTML에 적용할 때

- `<p>` 안의 긴 산문을 `<ul><li>` 중첩 구조로 바꾼다. `<span>` 안에 `<ul>` 같은
  블록 요소를 넣으면 구조가 어색해지므로, 컨테이너를 `<div>`로 바꾼다.
- 언어 토글이 있는 문서(en/ko span 병행)는 두 언어를 같은 불릿 구조로 대칭 유지하고,
  토글 CSS의 display를 inline이 아니라 block 기준으로 맞춘다.
- 목록 CSS를 같이 챙긴다: `ul` 들여쓰기, `li` 간격, 하위 목록은 폰트를 한 단계
  줄여 계층이 눈에 보이게 한다.
- 파이썬 빌더가 HTML을 생성하는 경우, 중첩 리스트를 받아 `<ul><li>`로 렌더링하는
  헬퍼 함수 하나를 만들어 쓰면 문자열 결합 실수를 줄인다. flexcat 리포트의
  `repro/report_widgets.py`에 있는 `bl()`이 실사용 예다.
- 수정 후 `<ul>`/`</ul>`, `<div>`/`</div>` 쌍의 개수가 맞는지 세어 구조 파손을
  확인한다.

## 하지 말 것

- 모든 문장을 기계적으로 불릿 하나씩으로 만드는 것. 짧은 두 문장이 한 주장이면
  한 불릿에 둔다.
- 산문이 더 맞는 자리까지 불릿화하는 것. 서사가 필요한 서론 한두 문장, 인용,
  수식 유도는 산문으로 둔다.
- 불릿화하면서 내용을 요약하거나 삭제하는 것. 삭제 판단은 ko-writing의 영역이고,
  이 스킬은 배치만 바꾼다.
