# ko-writing: 한국어 문체 단일 스킬

예전의 ko-prose와 fluent-korean 두 스킬을 이 폴더 하나로 합쳤다 (2026-09-04).
규칙 본문은 이 폴더 안의 파일에 있고, 여기서는 읽는 순서와 점검만 정한다.

## 사용 방법

1. 다음 두 파일을 전문 그대로 읽는다. 요약 금지(원저자 지시).
   - `ko-prose.md` (무엇을 빼는가: 자평, 직역, 비유, 3개 나열, 가운뎃점, 줄표, 부연 과다)
   - `fluent-korean.md` (어떻게 완성하는가: 조사와 어미, 전보문 금지, 엠대시 금지).
     코딩과 무관한 순수 글쓰기면 `fluent-korean-not-coding.md`를 대신 읽는다.
2. 여러 문단짜리 문서와 리포트를 통째로 쓸 때는 `doc-style.md`도 읽고,
   출력 직전에 `doc-checklist.md`를 돈다.
3. 세 문장을 넘는 답변, 보고, 리포트, 위키 페이지는 `humanreadable.md`도 읽는다
   (2026-10-21 추가). 쓰기 전에 1~4번(첫 줄, 이름 고정, 비교 수치, 남길 문장)으로
   설계하고, 문체 교정이 끝난 뒤 5~6번(계층 불릿, 표)으로 배치한다.
   `bulletization`과 `computational-section-writing`의 원칙을 일반 글에 맞게 옮긴 파일이다.
   HTML 변환 세부가 필요할 때만 `bulletization` 스킬을 따로 부른다.

## 역할 구분

- humanreadable.md: 설계와 배치 규칙. 결론 먼저, 대상 이름 고정, 두 값 비교,
  결정이 안 바뀌는 문장 삭제, 한 불릿 한 주장.
- ko-prose.md: 삭제 규칙. 자평과 중요도 과장, 영어 직역체, 구어 메타포,
  같은 근거의 반복, 결론을 바꾸지 않는 부연을 지운다.
- fluent-korean.md: 완성 규칙. 조사와 어미를 갖춘 완결 문장, 명사 나열식
  전보문 금지, 의미 성분 생략 금지.
- 충돌 시 우선순위: 사용자 글로벌 규칙(가운뎃점 금지 등) > fluent-korean > ko-prose.

## 독자가 모르는 약칭 금지 (2026-09-04 추가)

"버전 A/B", "플랜 ①/②", "단계 C" 같이 문서 안에서 내가 만든 약칭은 쓰지 않는다.
읽는 사람이 맥락 없이 그 문장만 봐도 알 수 있게 풀어 쓴다.
"로잔에 가면 / 안 가면", "10/17까지 DS-2019를 받으면 / 못 받으면"처럼 조건 자체를 적는다.
약칭이 꼭 필요하면 매번 뜻을 옆에 붙인다.

## 연구 리포트 구조 규칙 (2026-09-05 추가, CeO2 케톤화 리포트에서 확립)

- 캡션, 본문, Methods의 역할을 섞지 않는다.
  - 캡션: 그림에 무엇이 있는지, 조건(T, P), 버튼과 점선의 의미까지만. SI 캡션 스타일.
  - 본문 bullet: 수치, 해석, 순위 비교. 해당 figure 바로 아래에 둔다.
  - Methods: 계산 방법, 기준 상태, 샘플링 절차. 캡션에 "relax했다", "최저 구조다" 류 문구 금지.
- Results 서두는 "왜 이 경로들이 가능하다고 봤는지"를 산문 한 문단으로 열고, 그 뒤에 결과 bullet.
- 결론 섹션은 선행연구(원 제안 메커니즘)를 인용해 무엇이 같고 무엇이 다른지로 구성한다.
- Methods는 "볼드 주제 라벨. 산문 문단" 형식 (예: "에너지 계산. 모든 에너지는 ...").
- 열역학 입력값(엔트로피 등)은 계산값과 기준값(NIST 등) 대조 테이블을 Methods에 상설한다.
- 낡은 진행 요약과 중간 판정 섹션은 삭제하지 말고 문서 뒤로 옮겨 details 접기로 아카이브한다.
- 부차적 배경 섹션(원안 슬라이드, 원시 데이터 표)도 details 접기로 두고 본문 흐름에서 뺀다.

## 출력 직전 점검

- 서술어 없는 문장 파편이 있나.
- "핵심", "흥미로운" 류의 자평 수식어가 있나.
- 엠대시(U+2014)와 가운뎃점(U+00B7, U+318D)이 있나.
- 영어 직역 비유("실어 나르다", "배선")가 있나.
- 한국어 비유와 은유("닫는다", "벽에 부딪힌다", "길이 닫혀 있다", "그림자", "구름이 눕는다", "자리", "싹", "뛴다")가 있나 (2026-09-17 사용자 지시, 절대 금지). 사실 그대로의 말로 바꾼다.
- 내가 만든 약칭(A/B, ①/②)이 설명 없이 있나.
- 분야에서 영어로 부르는 개념을 억지 한국어로 옮긴 말이 있나 (2026-09-17 사용자 지시, 2026-09-21 재지시). **가장 자주 어기는 셋: "이완"은 relaxation, "학습 퍼텐셜"은 MLIP, "규약"은 functional이나 +U 유무로 쓴다.** 그 밖에 "범함수", "의사퍼텐셜", "묶음"(-> cohort), "판정", "처방"도 대상이다. 사전은 `domain-terms.md`이고, 내보내기 전에 그 표의 왼쪽 열 낱말을 grep으로 전수 검사한다. 도메인 용어는 영어 그대로 쓴다.
- 어려운 한자어(입경, 시료, 율속, 산입, 도출, 기인, 수반, 상이)가 있나 (2026-09-22 사용자 지시). 분야 용어면 영어로, 아니면 일상 한국어로 바꾼다. `domain-terms.md`의 "어려운 한자어" 표가 사전이다.
- 이 문장이 없으면 읽는 사람이 다른 결정을 하는가. 아니면 삭제.
- 제목, 표 머리글, 항목명이 구어 서술형인가 (2026-10-10 사용자 지시). "H가 가는 곳", "무엇이 바뀌나" 대신 "H 결합 자리", "변경 사항"처럼 용어로 된 명사구를 쓴다. 채팅 답변의 표와 bullet 머리도 포함한다.

## 문서 안 상호참조 표기 (2026-09-07 추가, 사용자 지시)

"절 3", "절 2.1" 같은 "절" 표기는 쓰지 않는다. 한국어 화자가 실제로 쓰지 않는 말이다.
상호참조는 "section 3", "section 2.1"로 쓴다. 괄호 안도 같다: (section 2, 3).
"결론 다섯 줄", "핵심 메시지" 같은 요약 상자 제목도 쓰지 않는다. "요약"으로 충분하다.
절 제목은 명사형으로 쓴다("계산 개요", "방법"). 질문형("무엇을 계산했나")과 결론 문장형 헤드라인("이온은 계면에 닿지 않는다")은 쓰지 않는다.
