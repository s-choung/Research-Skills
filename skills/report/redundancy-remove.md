
# redundancy-remove: 밀려난 내용 걷어내기

리포트는 한 번에 쓰이지 않는다. 궤적 1개로 절을 쓰고, 나중에 seed 30개가 들어오면 같은
관측량을 다시 그린다. 이때 **새 절만 추가하고 옛 절을 그대로 두는 일이 반복된다.** 독자는
같은 결과를 두 번 읽고, 둘 중 어느 쪽을 믿어야 하는지 스스로 판단해야 한다.

이 스킬은 리포트에 결과를 추가한 **직후에** 돌린다. 추가와 제거는 한 묶음이다.

## 언제 중복인가 (판정 기준)

두 블록이 다음을 **모두** 만족하면 뒤엣것이 앞엣것을 밀어낸 것이다.

1. **같은 관측량**을 보여준다 (같은 y축, 같은 카운트, 같은 지표)
2. **같은 계 또는 그 상위 집합**이다 (표면, 조성, 온도가 같거나 새 것이 옛 것을 포함)
3. 새 블록의 **근거가 더 강하다** (seed가 많다, 길이가 길다, 오차가 붙었다)

세 개가 다 맞으면 옛 블록은 지운다. "과정을 보여주려고" 남기지 않는다. 과정은 Methods에
한 줄로 적는다.

### 지우지 않는 경우

- 옛 블록에만 있는 **고유 정보**가 있다 (예: 첫 전이가 일어난 시각, 특정 구조의 스냅샷).
  이때는 그 한 줄만 새 절의 `<details>`로 옮기고 나머지는 지운다.
- 두 블록이 **서로 다른 질문**에 답한다. 같은 축을 써도 질문이 다르면 중복이 아니다.
- 옛 결과가 새 결과와 **어긋난다.** 이건 중복이 아니라 발견이다. 둘 다 남기고 왜 다른지
  적는다.

## 절차

1. **목록화.** 문서의 모든 `<h2>` 절에 대해 (관측량, 계, 근거 강도)를 표로 적는다.
   근거 강도는 seed 수, 궤적 길이, 오차 유무로 적는다.
2. **짝 찾기.** 관측량과 계가 겹치는 절 쌍을 뽑는다. 각 쌍에서 근거가 약한 쪽이 후보다.
3. **고유 정보 회수.** 후보 절의 불릿을 한 줄씩 읽고, 새 절에 없는 사실을 표시한다.
   표시된 것만 옮긴다. 옮길 게 없으면 그냥 지운다.
4. **제거.** 절 제목, 헤드라인, 불릿, 그림, 표, note, details를 통째로 지운다.
   **텍스트 상수와 table 정의도 같이 지운다.** 본문만 지우면 상수가 고아로 남는다.
5. **번호 재정렬.** Figure와 표 번호를 1부터 다시 붙인다.
6. **참조 수리.** 아래 grep을 전부 돌려 깨진 참조를 잡는다.
7. **재빌드.** 빌드 스크립트를 다시 돌린다. figure만 고치고 재빌드를 빼먹으면 화면은
   그대로다.

## 제거 후 필수 grep (하나라도 걸리면 고치고 다시)

```bash
# 끊어진 그림과 표 참조
grep -o "Figure [0-9]*" <out.html> | sort -u        # 번호가 연속인가
grep -o "표 [0-9]*\." <out.html> | sort -u
grep -c "Figure 4와 동일\|Figure [0-9]*와 같" <out.html>   # 사라진 그림을 가리키는가

# 방향 표현이 가리키던 절이 없어졌을 때
grep -c "다음 절\|앞 절\|위에서 본\|아래 두 그림" <out.html>

# 고아가 된 텍스트 상수
grep -n "^[A-Z_]* = \[" <build_report.py>          # 각 이름을 본문에서 다시 grep
```

`다음 절`, `앞 절`, `아래 두 그림` 같은 방향 표현은 절을 지우면 **조용히 거짓말이 된다.**
정적 검사가 못 잡으므로 이 grep을 반드시 돌린다.

## 자주 나오는 실수

- **본문만 지우고 상수를 남긴다.** `S_MD = [...]`, `MD_TABLE = table(...)`가 그대로 남아
  다음 사람이 "왜 안 나오지" 하며 되살린다. 정의까지 지운다.
- **번호를 안 고친다.** Figure 4를 지우고 5, 6, 7을 그대로 두면 독자가 빠진 그림을 찾는다.
- **"참고용으로" 접어서 남긴다.** `<details>`에 넣는 것은 제거가 아니다. 근거가 약한 옛
  결과는 접어도 여전히 두 번째 답이다. 고유 정보가 없으면 지운다.
- **재빌드를 안 한다.** HTML은 빌드 시점에 SVG를 인라인하므로 소스만 고치면 화면은 그대로다.

## 애초에 덜 생기게

- 결과를 추가할 때 **"이 결과가 밀어내는 절이 있는가"를 먼저 묻는다.** 추가와 제거를 같은
  커밋에서 한다.
- 수치는 json 하나에서 읽는다. 본문에 손으로 박은 수치는 새 데이터가 와도 안 바뀌고, 그
  자체로 옛 결과를 한 벌 더 남기는 일이다.
- 절 제목을 데이터 양이 아니라 **질문**으로 짓는다. "Seed 평균 캠페인"처럼 규모로 지으면
  규모가 커질 때마다 절이 하나씩 늘어난다.
